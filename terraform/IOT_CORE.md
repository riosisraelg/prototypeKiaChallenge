# AWS IoT Core Configuration

This document describes the AWS IoT Core resources created for the KIA Paint Shop IoT Prototype.

## Resources Created

### 1. IoT Thing
- **Name**: `kia-paintshop-prototype-simulator`
- **Purpose**: Represents the paint shop data simulator device
- **Authentication**: X.509 certificate-based

### 2. IoT Policy
- **Name**: `kia-paintshop-prototype-policy`
- **Permissions** (Minimum Privilege):
  - **Connect**: Allow connection with client ID `kia-paintshop-prototype-*`
  - **Publish**: Allow publishing to `kia/paintshop/*` topics only
  - **Subscribe**: Allow subscribing to `kia/paintshop/commands/*` topics
  - **Receive**: Allow receiving messages from `kia/paintshop/commands/*` topics

### 3. X.509 Certificate
- **Status**: Active
- **Files Generated**:
  - `simulator/certs/device.crt` - Device certificate
  - `simulator/certs/device.key` - Private key (permissions: 0600)
  - `simulator/certs/device.pub` - Public key
- **Attachments**:
  - Attached to IoT Thing
  - Attached to IoT Policy

### 4. IoT Rule
- **Name**: `kia_paintshop_prototype_ingest_rule`
- **Topic Pattern**: `kia/paintshop/+/+`
- **SQL Statement**:
  ```sql
  SELECT topic(3) as area, topic(4) as variable_id, * 
  FROM 'kia/paintshop/+/+' 
  WHERE timestamp IS NOT NULL
  ```
- **Action**: Invoke Lambda function `kia-paintshop-prototype-ingest`
- **Error Handling**: Log errors to CloudWatch Logs group `/aws/iot/rules/kia-paintshop-prototype`

### 5. IAM Role for IoT Rule
- **Name**: `kia-paintshop-prototype-iot-rule-role`
- **Permissions**:
  - Invoke Lambda function (ingest)
  - Write to CloudWatch Logs

## Topic Structure

The MQTT topic structure follows this pattern:

```
kia/paintshop/{area}/{variable_id}
```

Where:
- `{area}`: One of `pre-treatment`, `e-coat`, or `production-control`
- `{variable_id}`: Unique identifier for the variable (e.g., `PT-TEMP-001`)

### Examples:
- `kia/paintshop/pre-treatment/PT-TEMP-001`
- `kia/paintshop/e-coat/ED-VOLTAGE-005`
- `kia/paintshop/production-control/PC-SPEED-012`

## Message Format

Messages published to IoT Core should follow this JSON structure:

```json
{
  "variable_id": "PT-TEMP-001",
  "area": "pre-treatment",
  "timestamp": "2024-01-15T10:30:00.000Z",
  "value": 65.5,
  "unit": "°C",
  "quality": "good",
  "metadata": {
    "min_range": 60.0,
    "max_range": 70.0,
    "alarm_low": 62.0,
    "alarm_high": 68.0
  }
}
```

## Security Features

1. **X.509 Certificate Authentication**: All connections require valid certificates
2. **Minimum Privilege Policy**: Devices can only publish to `kia/paintshop/*` topics
3. **TLS Encryption**: All MQTT connections use TLS 1.2+
4. **IAM Role Separation**: IoT Rule has separate IAM role with minimum permissions

## Connection Information

After running `terraform apply`, the following outputs are available:

- **IoT Endpoint**: Use `terraform output iot_endpoint` to get the MQTT broker endpoint
- **Thing Name**: Use `terraform output iot_thing_name`
- **Certificate ARN**: Use `terraform output iot_certificate_arn`

## Simulator Configuration

The simulator should be configured with:

1. **Endpoint**: From `terraform output iot_endpoint`
2. **Port**: 8883 (MQTT over TLS)
3. **Certificate**: `simulator/certs/device.crt`
4. **Private Key**: `simulator/certs/device.key`
5. **CA Certificate**: Download from https://www.amazontrust.com/repository/AmazonRootCA1.pem

## Cost Considerations

- **Free Tier**: 500,000 messages/month
- **Current Usage**: ~259,200 messages/month (30 variables × 12 msgs/hour × 24 hours × 30 days)
- **Estimated Cost**: $0/month (within free tier)

## Monitoring

- **CloudWatch Logs**: IoT Rule errors are logged to `/aws/iot/rules/kia-paintshop-prototype`
- **Retention**: 7 days
- **Metrics**: Available in CloudWatch under AWS IoT namespace

## Cleanup

When running `terraform destroy`, the following resources will be deleted:
- IoT Thing
- IoT Policy
- IoT Certificate (deactivated and deleted)
- IoT Rule
- IAM Role and Policies
- CloudWatch Log Group

**Note**: Certificate files in `simulator/certs/` are generated by Terraform and will be recreated on next apply.
