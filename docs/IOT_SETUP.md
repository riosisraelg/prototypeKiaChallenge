# AWS IoT Core Setup Guide

This guide explains how to set up and use AWS IoT Core for the KIA Paint Shop IoT Prototype.

## Prerequisites

- AWS CLI configured with appropriate credentials
- Terraform >= 1.5.0 installed
- Python >= 3.11 (for simulator)
- `curl` command available

## Step 1: Deploy IoT Core Infrastructure

Navigate to the terraform directory and apply the configuration:

```bash
cd terraform
terraform init
terraform plan
terraform apply
```

This will create:
- IoT Thing (`kia-paintshop-prototype-simulator`)
- IoT Policy with minimum privileges
- X.509 certificate for authentication
- IoT Rule to route messages to Lambda
- IAM roles and policies
- CloudWatch Log Group for error logging

## Step 2: Verify IoT Core Resources

After successful deployment, verify the resources:

```bash
# Get IoT endpoint
terraform output iot_endpoint

# Get Thing name
terraform output iot_thing_name

# Get certificate ARN
terraform output iot_certificate_arn
```

## Step 3: Download Amazon Root CA Certificate

The simulator needs the Amazon Root CA certificate for TLS connection:

```bash
cd ..
./scripts/download_root_ca.sh
```

This downloads `AmazonRootCA1.pem` to `simulator/certs/`.

## Step 4: Verify Certificate Files

Check that all certificate files were created:

```bash
ls -la simulator/certs/
```

You should see:
- `device.crt` - Device certificate (generated by Terraform)
- `device.key` - Private key (generated by Terraform, permissions 0600)
- `device.pub` - Public key (generated by Terraform)
- `AmazonRootCA1.pem` - Amazon Root CA certificate (downloaded)

## Step 5: Test IoT Connection (Optional)

You can test the IoT connection using the AWS IoT Device SDK or mosquitto_pub:

### Using mosquitto_pub:

```bash
# Install mosquitto client (if not already installed)
# macOS: brew install mosquitto
# Ubuntu: sudo apt-get install mosquitto-clients

# Test publish
mosquitto_pub \
  --cafile simulator/certs/AmazonRootCA1.pem \
  --cert simulator/certs/device.crt \
  --key simulator/certs/device.key \
  -h $(cd terraform && terraform output -raw iot_endpoint) \
  -p 8883 \
  -q 1 \
  -t kia/paintshop/pre-treatment/TEST-001 \
  -m '{"variable_id":"TEST-001","area":"pre-treatment","timestamp":"2024-01-15T10:30:00.000Z","value":65.5,"unit":"°C","quality":"good"}'
```

### Using AWS IoT Test Client:

1. Go to AWS Console → IoT Core → Test
2. Subscribe to topic: `kia/paintshop/#`
3. Run the simulator (see Step 6)
4. You should see messages appearing in the test client

## Step 6: Configure Simulator

The simulator will automatically use the certificates generated by Terraform. Create a configuration file:

```bash
cat > simulator/config.yaml << EOF
mqtt:
  endpoint: "$(cd terraform && terraform output -raw iot_endpoint)"
  port: 8883
  cert_path: "certs/device.crt"
  key_path: "certs/device.key"
  ca_path: "certs/AmazonRootCA1.pem"
  client_id: "kia-paintshop-prototype-simulator"

simulation:
  interval_seconds: 30
  anomaly_probability: 0.05

variables:
  pre_treatment: "data/KMX-PA-PT-F-001.csv"
  e_coat: "data/KMX-PA-PE-F-001.csv"
  production_control: "data/production_control.csv"
EOF
```

## IoT Core Configuration Details

### Topic Structure

Messages must be published to topics following this pattern:

```
kia/paintshop/{area}/{variable_id}
```

Where:
- `{area}`: `pre-treatment`, `e-coat`, or `production-control`
- `{variable_id}`: Unique variable identifier (e.g., `PT-TEMP-001`)

### Message Format

```json
{
  "variable_id": "PT-TEMP-001",
  "area": "pre-treatment",
  "timestamp": "2024-01-15T10:30:00.000Z",
  "value": 65.5,
  "unit": "°C",
  "quality": "good",
  "metadata": {
    "min_range": 60.0,
    "max_range": 70.0,
    "alarm_low": 62.0,
    "alarm_high": 68.0
  }
}
```

### IoT Rule Processing

The IoT Rule extracts information from the topic and message:

```sql
SELECT 
  topic(3) as area,           -- Extracts area from topic
  topic(4) as variable_id,    -- Extracts variable_id from topic
  *                           -- Includes all message fields
FROM 'kia/paintshop/+/+' 
WHERE timestamp IS NOT NULL   -- Filters out messages without timestamp
```

The enriched message is then sent to the Lambda ingest function.

## Security Features

### 1. X.509 Certificate Authentication
- All connections require valid certificates
- Certificates are unique per device
- Private keys are stored securely (0600 permissions)

### 2. Minimum Privilege Policy
The IoT Policy only allows:
- **Connect**: With client ID `kia-paintshop-prototype-*`
- **Publish**: To `kia/paintshop/*` topics only
- **Subscribe**: To `kia/paintshop/commands/*` topics only
- **Receive**: From `kia/paintshop/commands/*` topics only

### 3. TLS Encryption
- All MQTT connections use TLS 1.2+
- Port 8883 (MQTT over TLS)
- Amazon Root CA certificate validation

### 4. IAM Role Separation
- IoT Rule has dedicated IAM role
- Minimum permissions to invoke Lambda and write logs
- No cross-service access

## Monitoring and Troubleshooting

### View IoT Rule Errors

```bash
# View recent errors
aws logs tail /aws/iot/rules/kia-paintshop-prototype --follow

# Query specific time range
aws logs filter-log-events \
  --log-group-name /aws/iot/rules/kia-paintshop-prototype \
  --start-time $(date -u -d '1 hour ago' +%s)000
```

### Check IoT Metrics

```bash
# Get number of messages published
aws cloudwatch get-metric-statistics \
  --namespace AWS/IoT \
  --metric-name PublishIn.Success \
  --dimensions Name=Protocol,Value=MQTT \
  --start-time $(date -u -d '1 hour ago' --iso-8601) \
  --end-time $(date -u --iso-8601) \
  --period 3600 \
  --statistics Sum
```

### Common Issues

#### 1. Connection Refused
- **Cause**: Incorrect endpoint or port
- **Solution**: Verify endpoint with `terraform output iot_endpoint`

#### 2. Certificate Verification Failed
- **Cause**: Missing or incorrect CA certificate
- **Solution**: Run `./scripts/download_root_ca.sh`

#### 3. Not Authorized to Publish
- **Cause**: Topic doesn't match policy
- **Solution**: Ensure topic starts with `kia/paintshop/`

#### 4. Messages Not Reaching Lambda
- **Cause**: IoT Rule not triggering or Lambda not created yet
- **Solution**: Check CloudWatch Logs for IoT Rule errors

  --statistics Sum

- Message count exceeds 400,000/month (80% of free tier)

## Cleanup

To remove all IoT Core resources:

```bash
cd terraform
terraform destroy
```

This will:
1. Deactivate and delete the certificate
2. Detach policy from certificate
3. Detach certificate from thing
4. Delete the thing
5. Delete the policy
6. Delete the IoT Rule
7. Delete IAM roles and policies
8. Delete CloudWatch Log Group

**Note**: Certificate files in `simulator/certs/` will remain but will be invalid after destroy.
