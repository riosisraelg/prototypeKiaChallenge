# Security Configuration - KIA Paint Shop IoT Prototype

## Overview

This document describes the security measures implemented in the KIA Paint Shop IoT Prototype to protect data and prevent unauthorized access.

## Encryption at Rest

### DynamoDB Tables

All DynamoDB tables have server-side encryption enabled using AWS managed keys:

- **sensor-data**: Encrypted with AES-256
- **alarms**: Encrypted with AES-256
- **statistics**: Encrypted with AES-256
- **variables-metadata**: Encrypted with AES-256

Configuration in `terraform/dynamodb.tf`:
```hcl
server_side_encryption {
  enabled = true
}
```

**Cost Impact**: No additional cost (AWS managed keys are free)

### S3 Bucket

The archive bucket has server-side encryption enabled:

- **Algorithm**: AES-256 (AWS managed keys)
- **Bucket Key**: Enabled for reduced API calls

Configuration in `terraform/s3.tf`:
```hcl
rule {
  apply_server_side_encryption_by_default {
    sse_algorithm = "AES256"
  }
  bucket_key_enabled = true
}
```

**Cost Impact**: No additional cost (AWS managed keys are free)

## Encryption in Transit (TLS)

### IoT Core MQTT

All MQTT connections use TLS 1.2 with X.509 certificate authentication:

- **Protocol**: TLS 1.2 (enforced)
- **Port**: 8883 (MQTT over TLS)
- **Authentication**: X.509 client certificates
- **Certificate Validation**: Required (CERT_REQUIRED)

Configuration in `simulator/mqtt_publisher.py`:
```python
self.client.tls_set(
    ca_certs=str(ca_path),
    certfile=str(cert_path),
    keyfile=str(key_path),
    cert_reqs=ssl.CERT_REQUIRED,
    tls_version=ssl.PROTOCOL_TLSv1_2,
    ciphers=None
)
```

**Verification**: AWS IoT Core endpoints use TLS 1.2+ by default

### API Gateway

API Gateway Regional endpoints use TLS 1.2+ by default:

- **Endpoint Type**: REGIONAL
- **TLS Version**: 1.2+ (AWS managed)
- **Certificates**: AWS managed certificates

Configuration in `terraform/api_gateway.tf`:
```hcl
endpoint_configuration {
  types = ["REGIONAL"]
}
```

**Note**: Regional API Gateway endpoints automatically use TLS 1.2 or higher. Custom domain names can enforce specific TLS versions if needed.

## Authentication and Authorization

### IoT Device Authentication (X.509)

Devices authenticate using X.509 certificates:

- **Certificate Type**: X.509 client certificates
- **Certificate Authority**: AWS IoT Core CA
- **Policy**: Minimum privilege (publish to kia/paintshop/* only)

IoT Policy in `terraform/iot.tf`:
```json
{
  "Effect": "Allow",
  "Action": ["iot:Publish"],
  "Resource": "arn:aws:iot:region:account:topic/kia/paintshop/*"
}
```

**Certificate Management**:
- Certificates generated by Terraform during deployment
- Private keys stored securely in `simulator/certs/` (gitignored)
- Certificates can be revoked via AWS IoT Core console

### API Authentication (API Keys)

All API endpoints require API key authentication:

- **Header**: `x-api-key`
- **Key Length**: 32 characters (randomly generated)
- **Usage Plan**: 1000 requests/day limit
- **Throttling**: 100 requests/second

Configuration in `terraform/api_gateway.tf`:
```hcl
api_key_required = true

quota_settings {
  limit  = 1000
  period = "DAY"
}

throttle_settings {
  rate_limit  = 100
  burst_limit = 200
}
```

**API Key Rotation**: Generate new key via Terraform and update dashboard configuration

## Public Access Controls

### S3 Bucket

Public access is completely blocked at multiple levels:

**Configuration in `terraform/s3.tf`**:
```hcl
resource "aws_s3_bucket_public_access_block" "archive" {
  bucket = aws_s3_bucket.archive.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

**What this blocks**:
- `block_public_acls`: Blocks new public ACLs and prevents existing public ACLs from being modified
- `block_public_policy`: Blocks new public bucket policies
- `ignore_public_acls`: Ignores all public ACLs on the bucket and objects
- `restrict_public_buckets`: Restricts access to buckets with public policies to AWS services and authorized users only

**Verification**: 
```bash
# Run security verification script
./scripts/verify_security.sh

# Or manually check
aws s3api get-public-access-block --bucket kia-paintshop-prototype-archive-{account-id}
```

**Result**: No objects in the bucket are publicly accessible under any circumstances

### API Gateway CORS

CORS is configured to allow dashboard access while maintaining security:

**Configuration in `terraform/api_gateway.tf`**:
```hcl
response_parameters = {
  "method.response.header.Access-Control-Allow-Headers" = "'Content-Type,X-Amz-Date,Authorization,X-Api-Key,X-Amz-Security-Token,x-api-key'"
  "method.response.header.Access-Control-Allow-Methods" = "'GET,POST,OPTIONS'"
  "method.response.header.Access-Control-Allow-Origin"  = "'*'"
}
```

**Security Measures**:
- API key required for all endpoints (x-api-key header)
- Rate limiting: 100 requests/second, 1000 requests/day
- Throttling prevents abuse
- CloudWatch logging tracks all access

**Note**: For production, replace `'*'` with specific dashboard domain:
```hcl
"method.response.header.Access-Control-Allow-Origin" = "'https://dashboard.example.com'"
```

### DynamoDB Tables

DynamoDB tables are not publicly accessible:
- **No public endpoints**: Tables only accessible via AWS API with IAM authentication
- **Access only via IAM roles**: All access requires valid IAM credentials
- **No internet gateway**: Tables exist in AWS internal network
- **VPC endpoints**: Can be added for additional isolation (not implemented to minimize costs)

**Verification**: DynamoDB tables cannot be made public - this is enforced by AWS

### Lambda Functions

Lambda functions are not publicly accessible:
- **No function URLs**: No public HTTP endpoints configured
- **Invocation via API Gateway only**: All public access goes through API Gateway with authentication
- **IAM-based invocation**: Direct invocation requires IAM credentials
- **VPC**: Functions run in AWS managed VPC (not customer VPC to minimize costs)

**Verification**:
```bash
# Check if any Lambda has a public function URL
aws lambda list-function-url-configs --function-name kia-paintshop-prototype-ingest
# Should return: ResourceNotFoundException (no URL configured)
```

### IoT Core

IoT Core endpoints are secured:
- **X.509 certificate required**: All connections must present valid certificate
- **TLS 1.2+ enforced**: No plaintext or weak TLS versions allowed
- **Policy-based authorization**: Certificate must have policy allowing specific topics
- **No anonymous access**: All connections must be authenticated

**Verification**: Try connecting without certificate - connection will be rejected

## Security Best Practices

### Certificate Management

1. **Storage**: Private keys stored in `simulator/certs/` (gitignored)
2. **Permissions**: Private key file has 0600 permissions (owner read/write only)
3. **Rotation**: Certificates should be rotated annually
4. **Revocation**: Revoke compromised certificates immediately via AWS IoT Core console

### API Key Management

1. **Storage**: API key stored in Terraform state (encrypted at rest)
2. **Distribution**: Share API key securely (never commit to git)
3. **Rotation**: Rotate API key if compromised
4. **Monitoring**: Monitor API usage via CloudWatch metrics

### IAM Best Practices

1. **Minimum Privilege**: Each role has only required permissions
2. **Resource Restrictions**: Permissions scoped to specific resources
3. **No Wildcards**: Avoid `*` in resource ARNs where possible
4. **Regular Review**: Review IAM policies quarterly

### Logging and Monitoring

1. **CloudWatch Logs**: All Lambda functions log to CloudWatch
2. **API Gateway Logs**: All API requests logged with details
3. **IoT Core Logs**: IoT Rule errors logged to CloudWatch
4. **Retention**: Logs retained for 7 days (balance between observability and cost)

## Compliance Notes

### Data Protection

- **At Rest**: All data encrypted with AES-256
- **In Transit**: All communications use TLS 1.2+
- **Access Control**: Multi-layer authentication (X.509, API keys, IAM)

### Cost Considerations

- **AWS Managed Keys**: No additional cost for encryption
- **TLS**: No additional cost (included in service pricing)
- **CloudWatch Logs**: Minimal cost (~$0.50/GB ingested)

### Limitations (Prototype)

This is a prototype system with the following security limitations:

1. **No VPC**: Services use public endpoints (acceptable for prototype)
2. **No WAF**: No Web Application Firewall (cost optimization)
3. **No GuardDuty**: No threat detection service (cost optimization)
4. **No Secrets Manager**: Certificates stored in files (acceptable for prototype)
5. **CORS Allow All**: API allows requests from any origin (should be restricted in production)

### Production Recommendations

For production deployment, consider:

1. **VPC Endpoints**: Isolate services within VPC
2. **AWS WAF**: Add Web Application Firewall to API Gateway
3. **GuardDuty**: Enable threat detection
4. **Secrets Manager**: Store certificates and API keys in Secrets Manager
5. **Custom KMS Keys**: Use customer-managed KMS keys for encryption
6. **Certificate Rotation**: Implement automatic certificate rotation
7. **CORS Restrictions**: Limit CORS to specific dashboard domain
8. **Rate Limiting**: Implement per-user rate limiting
9. **DDoS Protection**: Enable AWS Shield
10. **Security Auditing**: Enable AWS Config and CloudTrail

## Security Incident Response

### Compromised Certificate

1. Revoke certificate in AWS IoT Core console
2. Generate new certificate via Terraform
3. Update simulator configuration
4. Monitor CloudWatch logs for unauthorized access attempts

### Compromised API Key

1. Delete API key in API Gateway console
2. Generate new API key via Terraform
3. Update dashboard configuration
4. Review CloudWatch logs for suspicious activity

### Suspicious Activity

1. Check CloudWatch Logs for unusual patterns
2. Review API Gateway access logs
3. Check IoT Core connection logs
4. Verify IAM role usage in CloudTrail (if enabled)
